## Base URL and auth ([Authentication](https://past.dev/docs/memory-api/authentication/llms.txt))

- Base: `https://api.past.dev`, all routes under `/api/v1`. Call from a server; browsers are refused by CORS.
- Header: `Authorization: Bearer $PAST_API_KEY`. The docs name the variable `PAST_API_KEY`; our `.env` holds it as `PAST_DEV_API_KEY`; `gpuf.memory` accepts either.
- Key kinds: project key `past_sk_` (ingest, recall, audiences, identities, usage; selects one project, so no `projectId` in bodies); management key `past_mk_` (projects and keys only, reads no memory); agent token (short-lived, one person, project named by `X-Past-Project`, scopes `memory:read` / `memory:write`, not accepted on audience routes).
- Our key is accepted (usage returned 200, see below). Its kind is not stated in the response; we use it as a project key.

## Audiences ([PUT /api/v1/audiences/{slug}](https://past.dev/docs/memory-api/api-reference/llms.txt))

- Request: `kind` (required, `fixed` | `rule`), `name` (1 to 200 chars), `identities` (array, required for `fixed`; an unknown id is created), `rule` (required for `rule`: `{ match: all|any, conditions: [{ trait, operator, values }] }`, operators `is`, `is_not`, `is_one_of`, `is_not_one_of`, `exists`, `does_not_exist`; 1 to 20 conditions).
- Slug: 2 to 40 lowercase letters, digits, dashes, letter or digit at each end; `project` is reserved (it means project-visible). Response `201` on create, `200` on replace: `slug`, `name`, `kind`, `memberCount`, `memoryCount`, `reachesNobody`, `recomputedAt`, `createdAt`, `identities`, `rule`.
- Audiences must exist before a data point names them (`400 audience-unknown`). Audience routes accept keys only. Also: `GET /audiences`, `GET /audiences/{slug}`, `DELETE`, `POST /audiences/{slug}/recompute`.

## Identities ([PUT /api/v1/identities/{identity}](https://past.dev/docs/memory-api/api-reference/llms.txt))

- An identity is "your own id for a reader: a person, an agent or a service that calls recall" (1 to 200 chars, never generated by past.dev). `PUT` body `{ "traits": { "<key 1-200>": "<string value 1-2000>" } }` replaces the whole trait set; `PATCH` merges (null removes a key); `POST /identities/bulk` takes an array of `{ identity, traits }` (1 to 1,000). Response: `identity`, `traits`, `origin`, `lastSeenAt`, `createdAt`, `updatedAt`, `audiences` (only `GET /identities/{identity}` fills `audiences`, the slugs it reaches, including `project`).
- Identity on a data point is "the optional author, never the scope". Identity on a recall is the reader. An identity first named in a `fixed` audience or on a data point is created automatically (`origin` `audience` or `ingest`).
- A recall as an identity that reaches no audience returns project-visible memory only.

## Data points: date and audience ([POST /api/v1/ingest/batch](https://past.dev/docs/memory-api/api-reference/llms.txt), [Sending data](https://past.dev/docs/memory-api/sending-data/llms.txt))

- Body `{ "idempotencyKey": str<=200, "items": [ ... ] }`, 1 to 1,000 items, 16 MiB. Item fields: `content` (required, raw text), `id`, `label`, `timestamp`, `metadata` (any JSON; stored and returned, never filters recall), `audience`, `identity`. Single send: `POST /api/v1/ingest`, same fields plus `idempotencyKey`.
- Date: `timestamp` is ISO 8601 with a zone ("prefer UTC"); stored at microsecond precision; returned as `occurredAt`. Omitted: new data points take the send time, an existing id keeps its stored time. Backfilled history keeps its original date. The timestamp is "when the content occurred"; the unit is timed at its first message.
- Audience: slug string in `audience`. Omitted or `project` means project-visible (every identity reads it). A re-send without `audience` makes an existing data point project-visible.
- `id` must not contain `/` (`400 id-invalid`). Same id and unchanged content, label, metadata, timestamp: no-op. Same id and any change: replaces (old text and derived memory gone). No `id`: SHA-256 of content, so a corrected text becomes a second data point.
- Size: under 16,000 chars per conversation part, 32,000 per document part. Send raw text with a one-line header, never summaries.
- Response `202`: `projectId`, `ingestionId`, `status` (`queued`), `unchanged`, `items[{ordinal, sourceId, status, unchanged}]`. `200` with `status` `completed` and `unchanged: true` when nothing changed. Idempotent replay: same key and body returns the first receipt, same key with a different body is `409 idempotency-conflict`.
- Estimate: `POST /api/v1/ingest/estimate` (writes nothing, spends nothing). Not called by us (owner limit).

## Completion ([GET /api/v1/ingest/{ingestionId}](https://past.dev/docs/memory-api/api-reference/llms.txt), [Setup step 7](https://past.dev/docs/memory-api/setup/llms.txt))

- Poll until `status` is `completed` (others: `processing`, `failed`). Every 2 s for the first minute, then every 30 s; "a large send is processed for minutes to hours" and one project's sends are processed in order. Response: `status`, `settled`, `blocked`, `readiness{raw, comprehension, consolidation, failed}`, `failure` (`code`, `message`, or null). Polls cost nothing and are outside the per-minute limit.
- `failed`: `POST /api/v1/ingest/{ingestionId}/retry` (free). Failure codes include `model-unavailable`, `model-response-unreadable`, `index-unavailable`, `content-rejected`.
- Before completion a recall can already return the data points as `source` documents but none of their derived memory. Recall carries `pending` while any send in the project is processing. For measurement, wait for `completed` and `settled: true`.
- Typical completion time for a small batch: UNKNOWN (no figure given).

## Recall ([POST /api/v1/recall](https://past.dev/docs/memory-api/api-reference/llms.txt))

- Request: `query` (required), `identity` (required), `limit` (1 to 200, default 100), `level` (`low` 8,000 tokens default, `medium` 16,000, `high` 24,000, `extra-high` 32,000), `maxTokens` (not with `level`; plan ceiling 8,000 on Pay as you go and Flex, 32,000 on Enterprise), `queryTimestamp`, `occurredFrom`, `occurredTo`, `sort` (`relevance` default | `chronological`).
- Date bound: yes. `queryTimestamp` is "the perspective of the read. Evidence that occurred at or before this instant is eligible. Defaults to now." `occurredFrom` / `occurredTo` are inclusive bounds on occurrence time (`400 recall-range-invalid` if from is after to). Both are documented; whether `queryTimestamp` also hides memories whose source events straddle the bound (a derived claim combining an early and a late data point) is UNKNOWN. We send both `queryTimestamp` and `occurredTo` equal to the origin, and a second check in our code drops any result whose `occurredAt` is later.
- Response: `asOf`, `usedEvidenceTokens`, `results[]`, optional `pending`. Each result: `id`, `rank` (1.., no gaps), `occurredAt`, `content`, `artifact{ id, kind, occurredAt, supersededAt? }`, `sources[{ sourceId, occurredAt, label, excerpts[], metadata? }]`. `artifact.kind` is `source` (a data point returned verbatim) or a derived memory: `observation`, `claim`, `rule`, `membership`, `identity`, `mention`, `temporal-anchor`. Sources carry the `sourceId` we sent, the data point's date and quoted `excerpts`. Recall returns ranked documents, no generated answer. Whole documents are kept or dropped under the token budget.
- No filter on content or metadata. To read one scope, recall as an identity whose only audience is that scope (plus project-visible memory).

## Credits, plan, limits ([How requests behave](https://past.dev/docs/memory-api/how-it-works/llms.txt), [Concepts: Limits](https://past.dev/docs/memory-api/concepts/llms.txt))

- Send: 1 credit per 350 bytes of UTF-8 content, rounded up per data point, minimum 1 per data point. Unchanged re-sends, audience-only changes, idempotent replays, polls, deletes, estimates and refused calls cost nothing.
- Recall: 1 credit on Pay as you go. Flex and Enterprise: free within "fair use" (size UNKNOWN), 1 credit above it. No allowance caps recall counts.
- Requests per minute per key: 500 Pay as you go, 750 Flex, 1,000 Enterprise (fixed one-minute window on sends, recalls and answers). Over the limit: `429` with no body; wait 1 s and double on each repeat.
- Projects: 1 Pay as you go, 5 Flex, unlimited Enterprise (archived count). Audience count limit: none stated (fixed audience list: no limit; rule audience 20 conditions). Request-log payload retention 7 / 90 days / unlimited.
- Usage ([GET /api/v1/usage](https://past.dev/docs/memory-api/api-reference/llms.txt)): `month{from,to,resetsAt}`, `balance{left,included,bought,rolledOver,spent}`, `project{slug,credits,ingestions,recalls,creditCap,creditCapLeft,ingestionCap,ingestionCapLeft}`, `metered`. The response does not name the plan.

## Errors ([Errors](https://past.dev/docs/memory-api/errors/llms.txt))

Body `{ code, status, debugMessage, data }`, except the per-minute `429`, which has no body. Those we can hit: `400` `content-required`, `id-invalid`, `nul-character`, `invalid-ingestion`, `audience-unknown`, `audience-slug-invalid`, `audience-slug-reserved`, `audience-kind-invalid`, `audience-identities-required`, `audience-rule-required`, `identity-invalid`, `traits-invalid`, `identity-required`, `recall-query-required`, `recall-sort-invalid`, `recall-range-invalid`, `recall-level-invalid`, `recall-level-conflict`, `recall-budget-invalid`; `401` `missing-api-key`, `malformed-api-key`, `unauthorized`; `402` `out-of-credits` (`data.creditsLeft`, `data.creditsNeeded`), `project-limit-reached`; `403` `project-archived`, `insufficient-scope`; `404` `not-found`; `409` `idempotency-conflict`, `conflict`; `413` `content-too-large`; `429` `project-cap-reached`, `spend-cap-reached`, or no body; `503` `organization-not-ready`, `pipeline-disabled`. Retry a `429` after a pause, a `5xx` with the same `idempotencyKey`; fix the request on other `4xx`; never retry `402`.

## UNKNOWN in the docs

Plan name and audience count limit; how long a small batch takes to complete; whether derived memories that combine data points of different dates respect `queryTimestamp` and `occurredTo`; "fair use" size; whether recall ranking uses `label` and `metadata`; how an agent author (`identity` on a data point) shows in recall results (the reference lists `sources[].metadata` and `label` but no author field, so we put the author in `metadata.agent` and in the text header); whether `sort: chronological` plus `limit` drops the oldest or the least relevant.
